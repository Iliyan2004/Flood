#1 (Tab 5 damage dilution) — yes, this one is serious. It's not conditional on anything unusual: it fires on essentially every run, because "draw an arbitrary polygon, no bbox cap" is this app's whole premise, and CLAUDE.md's own numbers show a typical polygon fills ~64% of its bounding box. That means every Tab 5 "flooded %" and "mean damage fraction" per land-use class has been quietly diluted by dead, out-of-AOI cells on every run that's ever used a non-rectangular shape — which is most of them. This is the core deliverable of an entire tab, silently biased low, with no error or warning. I'd fix this first.

#2 (QVAR corner under-delivery) — real, but narrower. It only bites when someone's using the fluvial-hydrograph feature (not the more common constant-inflow or pluvial-only path) and the auto-detected river crossing happens to land within ~15-20m of the chosen edge's own corner. That's a plausible but not everyday combination. When it does hit, it's bad — you silently get less river discharge than you asked for, with the summary still claiming the full number — but it's not corrupting every run the way #1 is. Worth fixing, second priority.

#3 (1000× rain volume bug) — not currently serious. It's dead code today: the comment at that line is correct that the CUDA solver always logs exactly 0 in that column, so the buggy branch never actually executes right now — the analytical fallback always takes over. It's a landmine for later (an upstream LISFLOOD-FP fix or a CPU-path run would trip it), worth a one-line fix, but it is not producing any wrong number in the app as currently deployed.

#4 (missing theta / friction floor) — low real-world risk today, but worth closing. The UI default (0.05) is already in a safe range, so this doesn't affect any of the runs described in CLAUDE.md's history. It only becomes serious if a user deliberately dials friction down near 0 — the UI lets them, with no floor and no theta safety net, so the failure mode (solver blow-up) is real and matches LISFLOOD-FP's own documented warning. It's a missing guard rail, not an active bug.
